# 安装、升级、备份与迁移深入参考

本文件是 `../SKILL.md` 的深度参考。事实来源：官方文档
<https://docs.typecho.org/install>、<https://docs.typecho.org/upgrade>，
以及下载页 <https://typecho.org/download>。操作前先确认目标版本对应的实际要求。

## 1. 服务器环境要求

| 项目 | 要求 |
| --- | --- |
| PHP | 1.3.0 需 **7.4.0+**（官方 README 明示；安装程序不强制拦截，低版本会在解析阶段 fatal） |
| 数据库 | MySQL / PostgreSQL / SQLite 三选一，需装好对应 PDO 驱动 |
| 网络能力 | cURL 扩展 **或** Socket 支持，二选一 |
| 字符编码 | mbstring 扩展 **或** iconv 支持，二选一 |
| Web 服务器 | Apache / Nginx / IIS 等，能正常跑 PHP 并做伪静态即可 |

安装向导会自动检测上述条件，任一不满足会在页面上明确提示，按提示补齐扩展或
升级 PHP 后再继续。

## 2. 全新安装

### 2.1 目录结构

下载稳定版并解压后，关键文件与目录：

```
admin/       后台程序
install/     安装向导资源
usr/         用户数据：主题、插件、上传文件（升级时绝不能删）
var/         核心程序
index.php    入口
install.php  安装向导入口（安装完成后保留也无害，升级时会被替换）
license.txt  许可证
```

### 2.2 安装步骤

1. 把全部文件上传到 Web 目录（子目录或根目录均可）。
2. 浏览器访问站点目录，未检测到 `config.inc.php` 时自动进入安装向导。
3. 填写：
   - 数据库类型（MySQL / PostgreSQL / SQLite）；
   - 数据库地址、端口（MySQL 默认 3306）、用户名、密码、库名；
   - 表前缀（默认 `typecho_`，同库多站时改成不同前缀）；
   - 管理员账号、密码、邮箱与站点名称。
4. 安装成功后：
   - 安装程序在根目录生成 `config.inc.php`（含数据库连接与前缀，**不要泄露**）；
   - 页面给出**初始管理员密码**，立即复制保存，登录后台后修改。

### 2.3 忘记安装密码 / 需要重装配置

删除根目录的 `config.inc.php`，重新访问站点会再次进入安装向导。重新填写时
选择**保留 / 使用原有数据库**，即可在不丢数据的前提下重建配置与管理员入口。
切勿在未备份的情况下选择清空数据库。

## 3. 标准升级流程（文件替换 + 后台升级）

核心原则：**核心程序与用户数据物理分离**。升级只换核心文件，`usr/` 原样保留。

1. **先备份**：导出数据库，备份整个 `usr/` 目录与 `config.inc.php`。
2. 删除服务器上的旧核心文件 / 目录：
   - `admin/`
   - `var/`
   - `index.php`
   - `install.php`
3. **千万不要删除 `usr/` 目录**。主题、插件、上传的附件都在里面，
   核心升级不涉及它；误删会导致样式、功能与附件全部丢失。
4. 上传新版中同名的 `admin/`、`var/`、`index.php`、`install.php`
   （即删除后原样覆盖回新版本）。
5. 用**管理员账号**登录后台，系统检测到版本变化后提示升级，点击
   「**完成升级**」按钮，由升级程序迁移数据库结构。
   - 升级过程中前台短暂报错属正常现象，进后台完成升级后即恢复。
6. 升级完成后核对：文章 / 页面 / 分类 / 评论 / 附件数量与升级前一致。

### 3.1 升级后 500 / 白屏排查

绝大多数是旧插件或旧主题与新版本不兼容，按官方建议：

1. 进后台（若后台可进）**禁用所有插件**，并**启用默认主题**；
2. 确认站点在默认状态下恢复正常；
3. 逐个启用插件、恢复主题，每启用一个刷新一次，定位到具体的不兼容项；
4. 后台也进不去时，可通过文件系统临时重命名 `usr/plugins/` 下的可疑插件
   目录使其失效，恢复后再处理；插件 / 主题代码的 1.2 适配参见
   `../../typecho-plugin-development/SKILL.md` 与
   `../../typecho-theme-development/SKILL.md`。

### 3.2 1.1 → 1.2 代码命名迁移

- 数据库结构由后台升级程序自动迁移，无需手工改表。
- 需要人工修改的是第三方**代码命名风格**：

| 1.1 下划线风格 | 1.2 命名空间风格 |
| --- | --- |
| `Typecho_Plugin` | `\Typecho\Plugin` |
| `Typecho_Db` | `\Typecho\Db` |
| `Typecho_Widget` | `\Typecho\Widget` |
| `Typecho_Widget_Helper_*` | `\Typecho\Widget\Helper\*` |
| `Typecho_Widget_Helper_Form_Element_Text` 等 | `\Typecho\Widget\Helper\Form\Element\Text` 等 |

- 内置 Widget 的字符串短名（如 `'Widget_Options'`、
  `'Widget_Contents_Post_Recent'`）两版通用，迁移时可优先保留。
- 插件头信息、Hook 注册方式与目录结构不变；详见
  `../../typecho-plugin-development/references/structure.md` 与
  `../../typecho-plugin-development/references/lifecycle.md`。

## 4. 备份、换服务器、换域名

### 4.1 完整备份三要素

一份能完整恢复站点的备份必须包含：

1. **数据库导出**（mysqldump / pg_dump / SQLite 文件，或后台工具导出）；
2. **整个 `usr/` 目录**（插件、主题、上传附件）；
3. **根目录 `config.inc.php`**（数据库连接信息与表前缀）。

只备份数据库而漏掉 `usr/`，恢复后会丢附件与界面；反之亦然。

### 4.2 更换服务器

1. 在新服务器安装**同版本** Typecho（确保环境满足第 1 节要求）；
2. 导入数据库备份；
3. 用备份的 `usr/` 覆盖新机的 `usr/`；
4. 按新机环境修改 `config.inc.php`：数据库地址、账号、密码、库名、
   表前缀必须与导入的库一致；
5. 检查伪静态规则与目录权限，验证前台、后台、附件上传。

### 4.3 更换域名

1. 在后台「设置 → 基本」中更新站点地址；
2. 文章正文、附件地址中写死的旧域名绝对 URL，需要另行批量替换数据库内容
   （操作前务必备份，并用脚本 / 工具按字段安全替换）；
3. 如有伪静态、CDN、HTTPS 跳转配置，同步更新。

## 5. 已过时的部署形态

历史资料中可能出现 GAE / SAE / BAE / ACE 等云引擎的专门部署说明，这些平台
与对应适配方案均已过时，现代部署直接按第 1～3 节的标准 LAMP/ LNMP 流程
操作即可，不要沿用旧文档里的上传协议或特殊目录约定。
